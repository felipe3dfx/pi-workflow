## Implementation decisions and limits

The optional parent `consult` adapter is an operation-specific inference/transport seam, not a new transport. Its trusted resolver must obtain user authority when parent authority is insufficient. A child always uses its own existing `spec.ask` path, never the parent resolver's captured executable. A JSON envelope on existing correlated text replies carries identity, original proposal, explicit response kind and answer, plus optional exact confirmed actions. A session-local random consultation ID also prevents cross-child or later-call answer reuse when SDK call names/IDs happen to coincide. Unknown responses are narrowed at runtime; no text acknowledgment parser or automatic approval fallback exists.

Resolved evidence augments the proposal, not the caller's mutable authority. The semantic adapter must assess the answer with original/current task/instruction precedence. Both initial and resumed assessments apply the same exact high-impact confirmation rule. The initial missing-confirmation hold enters consultation too, even if a classifier returned `confirmed: true`. Explicit deny does not become a technical failure. Pending, malformed replies, failed delivery and unavailable classification remain recoverable holds. The optional resolver is called at most once per invocation; there is no retry loop.

Held consultations enter session-local pending state before the wait so cancellation/result capture retains the action. Every SDK invocation ID is reserved synchronously before asynchronous evaluation; repeats cannot execute or spend another response. Success still passes #290's final authority observation after the last awaited decision delivery, then synchronous prompt/binding/full-action/abort checks; no notification/retry/await follows the release check. All execution remains in the SDK pipeline. Original adapter receivers/prototype methods and host `bindSession` ownership are preserved.

Foreground pending is a new result variant of the existing launch operation, explicitly marked `launched: true`, not the pre-launch refusal message. It carries proposals, current reason, text, result and checkpoints. Parent consultation followed by an explicit fresh spawn is the recovery path; no retained foreground conversation or automatic background conversion is introduced. Completed background results carry pending proposals in structured details and model-facing content even if the child's free-text/Verdict claims completion; existing explicit continuation re-proposes under current authority and does not replay stored tool execution. Background result delivery, consumption and conversation retention remain their existing mechanisms.

No accepted ADR bytes, glossary, dependencies, tool sources, routing, checkpoint policy, default production path, model/cache/budget or adoption decision changed. ADR 0021 readback remains SHA-256 `154998e43f34de5516a09fa47766277ecdedb1ac295265dc0ffb35c82c7d1352`.
