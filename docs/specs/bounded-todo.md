## Intent and authority

Bound the Todo so long lists remain navigable without consuming the conversation, expose the existing done filter, and support mouse and keyboard. Stories: an operator can browse tasks in their original order, reverse a filter, collapse and reopen Todo without changing tasks, and operate it when space or mouse support is limited. The user is resolver for all product decisions; the brief identifies the issue comments for each approval. The Todo-only scope and combined-panel clipping risk were expressly accepted in [6853940782](https://github.com/felipe3dfx/pi-workflow/issues/364#issuecomment-6853940782); no shared allocation guarantee is implied. GLOSSARY.md supplies canonical Todo, Task state and Shell; Domain Authority Handoff was not supplied, an admissible evidence gap with semantics closed. ADR 0007 requires using the public widget API where available; no new ADR is needed.

## Required behavior

The following arithmetic and thresholds are **derived specifications**, not verbatim user wording. The approved outcomes and their sources are in the brief.

- Let `B = floor(terminal.rows / 3)`, counting every Todo-emitted row, including margins, frame and controls. Zero tasks emits zero rows. With tasks and terminal rows 1–2, emit zero rows even when manually collapsed. From 3 rows, manual collapse takes precedence and emits exactly one clickable line.
- Otherwise `pageCap = max(0, min(8, B - 5))`, reserving two margins, two frame rows and one control row unconditionally. If `pageCap < 1`, emit exactly one automatic compact line without margins or controls, with count, filter and as much keyboard hint as width permits. Compact is derived at render, never stored as manual collapse. At 18 rows expanded mode begins. At 39 rows the cap first reaches eight. Never exceed B. When controls are absent actual overhead is four rows, but capacity still reserves five.
- In expanded mode controls appear exactly when the **unfiltered** task count is at least `pageCap`. Filtering never hides them while this condition holds; no historical latch exists and data changes or resize recompute it. A qualifying filtered-empty view retains controls and a filtered/total `0/N` indication, without an extra empty message row. Below threshold preserve the existing blank framed branch for an empty filtered result; the filter shortcut reverses it. Do not promise counts in an absent control row.
- Reuse the single existing `showDone` predicate; default English chrome is All / Without done, retaining pending, in-progress and blocked tasks in the latter. Both clicking and existing `Alt+Shift+H` toggle this same state and reset page to one. No individual Task state filters. Keep `Alt+Shift+T` for manual collapse. Preserve original ordering; neither state updates nor the working task automatically select a page. While `pageCap < 1`, retain the current page and filter without dividing by zero or calculating an empty page count; a user filter change still resets the page to one. Defer clamping for data and height changes during compact mode. Manual collapse likewise preserves the current page. On the next expanded render with `pageCap >= 1`, calculate `pageCount = max(1, ceil(visibleCount / pageCap))` from current data and clamp the current page to `1..pageCount`. Persist that clamp as current; enlargement must not resurrect an old page or a stale snapshot. For example, page 7 remains 7 on entering compact; if the next expanded render has three pages, it becomes 3. Existing tool-mutation reveal behavior stays unchanged; compact rendering itself does not write collapsed state. No new persistence or unsupported session-reset semantics.
- Pagination and filter controls are clickable in fullscreen. × responds only on its actually rendered glyph and collapses like `Alt+Shift+T`; a manually collapsed line responds on its visible cells to reopen. Reopening into insufficient space displays automatic compact; that automatic line is not a new toggle. Clicks do not change task data or call a tool. Global keyboard equivalents remain usable in non-fullscreen, where mouse belongs to the terminal.
- Derive hit regions from the actual rendered logical cells after ANSI sanitization and horizontal truncation. Events outside their x/y spans remain unhandled, and stale geometry must not act. The public API does not expose host vertical allocation or clipping to this widget: rely on host hit-testing bounds for physically unallocated coordinates, and do not claim all vertical clipping cases are solved. The accepted limitation is combined-panel clipping only, not acceptance of accidental invisible click actions. For widths that cannot fit every control in one row, never wrap or create false hit regions: prioritize the current filter/count, then page position, then navigation and filter click targets, then hints; retain keyboard access for omitted targets. This ordering is a deterministic derived presentation rule; exact wording and styling are recommendations. Display inline key hints when width permits.

**Recommendation, not binding product choice:** use `Alt+Shift+P` / `Alt+Shift+N` for previous / next, bounded without wrap. Public 1.4 and local 1.5.0 default binding sources show no literal collision; verify installed 1.5.2 defaults before binding, and account for user remaps, extensions and terminal encoding. Keyboard pagination must exist regardless of final key choice.

## Design constraints and seams

Mandatory: retain Shell's child-session-then-Todo ordering, sibling isolation, accurate hit geometry and event translation; unhandled events outside Todo remain unhandled by it. Use the public widget factory/component, mouse and live terminal rows rather than a host-internals patch (ADR 0007); public 1.4 sources support this interface and the declared floor, as does inspected local 1.5.0. These source observations do not prove runtime integration. Preserve existing consumers and avoid any global panel budget.

Recommendation: deepen the existing Shell widget seam with minimal live row context and optional per-occupant mouse handling; record rendered occupant ranges and translate x/y correctly. This preserves the render-only adapter, localizes layout knowledge and permits testing through the widget factory. Do not migrate `children-box` absent a demonstrated need. Resize requests a render, not necessarily invalidate: recompute from live rows on every render and avoid a width-only stale cache. The bounded seam is an implementation obligation, not a prerequisite claim that integration already works.

Plan a presentation-only specification delta to `docs/specs/child-session-delegation.md` and `docs/specs/todo-child-link.md` when implementing, preserving their behavioral contracts. These presentation changes are future work. See [source evidence](#source-evidence).

## Acceptance and future validation

At the highest useful existing seam, exercise zero tasks, all done and empty filtered results; heights 1, 2, 3, 17, 18, 38, 39; unfiltered counts cap−1, cap, cap+1; complete row budgets including margins and control visibility. Exercise page/filter change, data mutation, shrinking/enlarging, clamp persistence, manual collapse, compact transition and height-only resize. Verify x, reopen, page and filter mouse geometry, translated coordinates, margins, siblings, horizontal truncation and stale logical regions; test routing through the host for vertical allocation and clipping; if proportionate use the existing fullscreen host-dispatch harness as well. Run real-terminal fullscreen clicks and keyboard, non-fullscreen keyboard, and the expressly accepted combined clipping scenario with a working child session. Confirm public API behavior and installed 1.5.2 key defaults at implementation time. Run `npm run check` on the exact implementation head and record result; mutation testing is unsupported by native policy and is not a blocker. Earlier investigation's 180-second timeout was incomplete, not feature validation. No runtime, real-terminal or implementation validation is claimed here.
