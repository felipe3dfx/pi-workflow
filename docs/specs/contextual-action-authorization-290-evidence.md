## Implementation decisions

- `action-authorization.ts` is the shared local mechanism. A configured semantic adapter assesses actual invocation facts, effective system/project instructions and separately supplied task authority. Tool descriptions/schemas/hints/quoted inputs remain evidence. Missing/malformed/failing evaluation and cancellation produce retained `held` records and visible reasons; actual prohibition produces `deny`. No command-name permission inventory or role/Jev permission field is supplied to that mechanism.
- High-impact dispatch additionally matches exact tool/input/cwd against the current authority's `confirmedActions`; a classifier's boolean cannot invent confirmation for another action/target. Authority, effective instructions and invocation facts are checked again before release. This is a structural input contract, not a model/provider choice or full #291 reply protocol.
- `contextualWorkflowSources` is an unadopted SDK host composition seam: explicit selected paths + cooperative factories + common native factories are instantiated in parent and child. Host-selected trust is preserved; no arbitrary child-worktree extension discovery or private closure replay is introduced. The actual parent launch forwards authorization/sources into real SDK child construction. Relative selected paths resolve against the parent's project directory, not the child's assigned worktree, so configuration does not silently select a different file. Failed selected source loading is visible, not a silent fallback to a role inventory.
- Owned child data/tool factories are headless. Todo does not install parent painters/shortcuts; children-box/header UI is not attached; operator factories receive a local close callback rather than closing the parent's global view. Owned source updates act on each local registered instance. Native registered/active/callable/UI-readiness distinctions remain real; hidden tools cannot be activated merely by name.
- Contextual Contract/guidance and Jev destination prompts replace conflicting general role/command reservations only in the injected path. The default operational path remains unchanged/unadopted. The contextual shell removes the general git/gh inventory but retains the existing add/commit checkpoint route for #292; no signing/grant policy is relaxed here. The contextual CodeGraph uses the same local-context factory, not a role-specific read-only source subset. Selected external web sources come from the common recipe, not explorer-only discovery.
- GREEN simplification: one authorization snapshot is enriched rather than rebuilt, native deep equality compares current facts, and each child binds its extension runtime once. The latter prevents repeated local prompts from restarting source/MCP lifecycles (observed 5 starts instead of 1 before the fix).
