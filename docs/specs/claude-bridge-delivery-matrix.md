# Claude Bridge delivery coverage record

This record documents verified evidence for the bounded delivery slice of issue #240. It supplements, and does not replace or narrow, [`claude-bridge-support.md`](./claude-bridge-support.md). Results apply only to the exact installed packages, model IDs, and runs stated here; they do not claim universal compatibility.

## Environment and source boundary

- Pi CLI `1.2.0`; Pi SDK packages `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai` `1.0.4`.
- Real installed provider source: developer-configured user npm package `pi-claude-bridge` `0.9.2`, with no version pin. This is the only real installed-source coverage approved for this delivery.
- `pi auth check --provider openai-codex --json --no-refresh` returned `{"status":"ready","provider":"openai-codex","authType":"oauth"}`; no credential values were printed. Mixed-profile tests use a read-only credential store whose write/delete methods throw.
- The actual installed git Bridge source is absent from the configured package inventory. Git real-install coverage was not run and remains a limitation. No package was fetched or installed. Git-shaped and local source fixtures test identity recognition only, not real installs.
- Source resolution evidence is in `test/child-sessions.test.mjs`: actual installed npm identity/resource; git-shaped/local fixture identities; malformed/unreadable/missing/mismatched resources; no-install policy; source filters; trusted project precedence; untrusted project shadowing; parent cwd rather than child cwd; unrelated local resources; and ambiguity. Fixtures do not enlarge the real-source coverage claim.
- The approved integration batch rule explicitly covers this source-coverage delta. It still requires the complete handoff, terminal findings, and green `npm run check` in the integrated tree before #240 can close. This documentation pass does not claim the entire ticket is complete.

## TEST10 seam disposition and historical evidence

The former opt-in SDK-only `TEST10: a real Bridge parent spawns a real Bridge child...` case in `test/claude-bridge-live.test.mjs` was removed: it manually assembled `createAgentSession` and a `DefaultResourceLoader`, so it was a parallel SDK seam rather than the configured Pi RPC path. It duplicated the parent-spawn/wait/result/recall question while providing less representative lifecycle evidence than `test/rpc-test10.test.mjs`. The latter is the retained end-to-end oracle for that question and verifies structured queued-to-completed delivery through public RPC events. Direct actual Bridge child/manager behavior remains covered by the separate role, tools, F1, cancel, Steer, timeout, and failure cases listed above.

The original failing SDK-only probe's prior raw output is not retained in this checkout; no historical failure details are reconstructed here. The corrected RPC run is the retained successful JSONL artifact named above.
