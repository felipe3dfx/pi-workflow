# ADR 0013: Child command policy for git and gh

## Status

Acceptance: approval and merge of the introducing PR.

## Decision

A child session reads `git` and GitHub state on its own. Commands that mutate the repository or the remote, or publish, stay with the parent. For `git` the policy is a denylist: everything not listed runs, and the list grows only with evidence from a real session. For `gh` it is an allowlist of reads: everything not listed is refused. It applies the same way whether Jev routing is on or off.

The child's `bash` runs each command after a harness-owned prefix, set through the bash tool's `commandPrefix` option, that defines the shell functions `git` and `gh`. The prefix is two lines: `unalias git gh 2>/dev/null`, then the guard on one line. The user's `shellCommandPrefix` global setting still applies: it runs first, followed by the two guard lines. The line numbers in a bash error therefore point 2 + N lines below the command's own line, where N is the line count of the user's prefix, or 0 without one. The `unalias` line stands alone because bash expands aliases when it parses a line, so a user prefix that enables `expand_aliases` and aliases `git` or `gh` would otherwise break the function definitions. The user's `shellPath` global setting is not used: the functions are POSIX shell code that a shell such as fish cannot parse, so the child always runs under the tool's own `/bin/bash -c`. Project settings are not read, because the child's directory carries no trust decision. When the child's directory cannot be resolved to its physical path, the guard uses the path as given and the launch proceeds. The functions are not exported and are POSIX `sh`, run by the tool's `/bin/bash -c`; their helpers carry a `__pi_workflow_` prefix and keep their variables in a subshell. They expand no unset variable, so a user prefix with `set -u` does not abort them. A function decides from the command words it receives and the working directory. When it allows a command, it runs the real program with `command git "$@"` or `command gh "$@"`. When it blocks one, it writes this message to standard error and returns 126:

"`<command>` is reserved for the parent. Continue without it and list the exact command in your result; do not ask the parent to run it."

`<command>` is `git <subcommand>`, `git <subcommand> <verb>`, `git -c alias`, or `gh <group> <verb>`, and `gh <group>` when there is no verb. The message names no role and does not invite `ask_parent`.

The functions guard only the model's own command line, including its pipelines, subshells, and command substitutions. Processes it starts, such as npm scripts, `git` hooks, husky, lint-staged, tests, `sh -c`, and `xargs`, run the real programs. This replaces the `PATH` stubs of ADR 0011, which every descendant inherited, so a child's `npm run check` or commit hook failed with exit 126 on its own `git` calls.

The `git` function blocks only when the physical working directory (`pwd -P`) is the child's worktree root or inside it. Elsewhere, such as a temporary repository a test creates, it runs the real `git`. It finds the subcommand by skipping every leading global option. The options `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--exec-path`, `--config-env`, and `--attr-source` also consume the next word; their `=` forms are one word. An option alone never blocks, so `git -c color.ui=never log` and `git --no-pager diff` run, except a `-c` value, separate (`-c alias.ci=commit`) or attached (`-calias.ci=commit`), whose key starts with `alias.` in any case: it is blocked as `git -c alias`. These subcommands are blocked as a whole: `commit`, `merge`, `rebase`, `cherry-pick`, `revert`, `am`, `reset`, `tag`, `branch`, `update-ref`, `push`, `pull`, `fetch`, `checkout`, `switch`, `restore`, `clean`, `stash`, `add`, `rm`, `mv`, `apply`, `config`, `worktree`, `gc`, `notes`, `bisect`, `sparse-checkout`, `update-index`, `read-tree`, `symbolic-ref`, `replace`, `filter-branch`, `prune`, `stage`, `send-email`, `maintenance`, and `repack`. For `remote`, `submodule`, `reflog`, and `lfs` the function reads the next word that is not an option and blocks only mutating verbs: `remote` `add`, `set-url`, `remove`, `rm`, `rename`, `update`, `prune`, `set-head`, and `set-branches`; `submodule` `add`, `update`, `init`, `deinit`, `sync`, `foreach`, `absorbgitdirs`, `set-branch`, and `set-url`; `reflog` `expire` and `delete`; and `lfs` `push`. Reads such as `git remote -v`, `git remote get-url origin`, `git submodule status`, and `git reflog` run.

The `gh` function decides from any directory, because `gh` acts on the remote. It finds the group and the verb by skipping `-R` and `--repo` with the next word, and `--repo=<value>`. Any other option before the verb refuses the command as `gh <group>`, because `gh` may read the next word as that option's value: in `gh pr --subject view merge 12`, `gh` runs `merge`, not `view`. Options after the verb, as in `gh pr list --state open`, are not read. It allows the verbs `view`, `list`, `diff`, `checks`, `status`, `watch`, and `download` in any group, the whole `search` group, `repo clone`, `help`, and `gh` with no group, including `gh --help` and `gh --version`. Everything else is refused, such as `gh api`, `gh pr create`, `gh pr checkout`, `gh pr revert`, `gh repo set-default`, `gh repo autolink create`, and `gh project item-add`. The `gh` policy is an allowlist because three review rounds of the denylist kept finding nested or unknown mutating verbs and option values read as the verb; an allowlist fails closed.

Supersedes: ADR-0011. This reverses its clause, accepted in #166, that the child's `bash` runs `git` and `gh` unchanged while Jev routing is on, and replaces its `PATH` stubs with shell functions. A Jev-on child no longer commits or pushes.

## Considered Options

- Keep ADR 0011: block all `gh`, and all `git` inside the worktree, only while Jev routing is off. Rejected: children asked the parent for plain reads such as `git status` and CI logs, and the Jev-on branch let a child commit and push.
- An allowlist of read commands for `git`. Rejected: every missing read becomes a question to the parent, which is the cost this policy removes.
- A denylist hardened by session evidence for `git`. Chosen.
- A denylist for `gh`. Rejected: three review rounds kept finding nested or unknown mutating verbs, such as `gh pr revert`, `gh repo set-default`, and `gh repo autolink create`, and option values read as the verb.
- An allowlist of read verbs for `gh`. Chosen: it fails closed.
- Keep the `PATH` stubs. Rejected: every descendant inherits `PATH`, so the stubs refused the `git` calls of hooks, npm scripts, and tests that the child ran legitimately.

## Consequences

A child runs `git status`, `git diff`, `git log`, `git show`, and `gh` reads without asking. A blocked command fails non-zero, and the child lists it in its result for the parent to run. Tests, hooks, and tools keep working, including `npm run check` inside a child, because they run outside the model's command line or outside the worktree.

Deferred until a real session shows the need: `git` config alias and `gh` alias resolution; the `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_CONFIG_*` environment overrides; absolute-path invocations of `git` or `gh`; the physical-path comparison on Windows and Git Bash, where `pwd -P` and the resolved worktree path use different forms; guards for the shell programs `rm` and `find`; and SQL.

Accepted risks:

- R1: the `git` denylist lets unanticipated mutating subcommands through, and both functions let config aliases, `gh` extensions invoked with an allowed verb, environment overrides, absolute paths, `command git` and `command gh`, descendant processes such as `sh -c`, `xargs`, and npm scripts, and `git -C <worktree>` or `--git-dir` invoked from outside the worktree through. A user prefix that redefines `unalias`, `command`, or the guard functions is out of scope. The functions guide the model; they are not a security boundary. In-process tools such as the `codegraph` tool do not go through them.
- R2: whole-command blocks also refuse some reads: `git branch --list`, `git config --get`, `git tag -l`, `git fetch`, `git bisect log`, and `git sparse-checkout list`. The `gh` allowlist refuses reads outside it, such as read-only `gh api`, `gh repo autolink list`, `gh variable get`, top-level `gh status`, `gh browse`, and help forms after a group such as `gh pr --help`, while its verbs allow reads in sensitive groups, such as `gh auth status`, `gh secret list`, and `gh release view`. Harden or relax only with evidence.
