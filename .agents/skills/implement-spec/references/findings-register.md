# Children's Findings Register

Read this file before the parent's first review at step 6.

Build the register from the children's `implement` handoffs with one entry per finding a child rejected or the developer decided, such as an answered `user decision` or an accepted risk. Never register a finding accepted and fixed, so the parent review still raises a fix lost in a merge or overwritten by a sibling.

Each entry carries the finding's ticket, ID, axis, location, claim, evidence, terminal verdict with the critique's evidence or reason for it, and the developer's decision where one exists. Take the axis, location, claim, and evidence from the handoff's review report, and the verdict, its evidence or reason, and the decision from its findings list; copy each, never write or rephrase it.

A `TRADE` the developer decided comes from the critique, not the review report. Register it under each finding ID the trade names, with that finding's fields as above and the trade with the developer's decision as the decision.

Hand the register to the first parent review, to every parent re-review, and to every parent critique.
