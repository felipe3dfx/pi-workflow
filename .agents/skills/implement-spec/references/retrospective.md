# Retrospective

Read this file before writing the report.

List the run's misses, each once, from what the run already holds; never re-run a step to find more:

- a parent review finding, accepted or decided by the developer, that no child's review raised, meaning no child's review report holds the same claim at the same location or requirement;
- a finding that developer feedback, a red publication gate, red CI the change caused, or `qa-impact` raised after the parent review;
- a finding the critique rejected that the developer later had applied;
- a miss a child's handoff retrospective reports, listed once.

Give each miss its cause, one of unclear ticket or specification, missing context, missing or misjudged check, or repeated manual step, and the smallest durable change it suggests, naming the skill, playbook, or ticket that change would edit. When the miss belongs to the work itself, say `no system gap`. Propose only: the retrospective edits nothing and publishes nothing. With no misses, say so.
